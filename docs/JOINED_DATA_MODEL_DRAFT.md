# 突合後データの保存設計（v0.2 / 30軸対応・画像候補追加）

- 作成日：2026-10-16
- 対象：`valid-app-sheets`
- 状態：**2層構成を初版の設計ベースに採用。列定義の詳細・機微項目と復旧方式は設計案、未実装**
- 確定前提：コンテナバインドGAS、ブラウザ内CSV正規化・突合、RAW非保存、**毎回全件置換**、個人情報を減らしつつ再集計可能にする、全件分析
- 参照：既存[valid-appの分析軸仕様](https://github.com/tsicb/valid-app/blob/main/docs/ANALYSIS_AXIS_AVAILABILITY.md)、`index.html` の `APPLICATION_DATA_HEADERS`／`JOB_ANALYSIS_HEADERS`／`buildNormalizedSheetsModel()`

## 1. 基本方針

既存Web版の「応募1件1行（applicationData）＋求人1件1行（jobAnalysisMaster）」という**2層モデルを保持**する。ただし、ユーザーが普段見る突合一覧は1タブとする。

1. **`20_突合データ`（表示）**：応募1件=1行。確認しやすいよう、代表的な求人属性を一部重複表示する。
2. **`93_求人分析マスタ`（内部・非表示）**：求人1件=1行。給与、画像、Indeedタグ、原稿文字数などを保存。`求人参照ID` で関連付ける。
3. **画像URL・取得状態**は画像マスタ（別途設計）に管理し、必要な場合は既存Workerで再取得。求人データ本体に取得ログを混ぜない。
4. **KW／企業ID表示名／Indeedタグ名称**の編集マスタはシート上に用意し、保存データ側では**元の仕事名・コード**を残す。マスタ変更後は再集計だけで対応する。
5. 分析の基準単位は**応募レコード**。求人件数は重複しない求人参照IDなどを別途数える。Indeedタグのような複数値軸ではタグ合計≠全応募となり得る。

## 2. `20_突合データ` 保存列（23列案）

| 列 | 保存する項目 | 形式／理由 |
|---|---|---|
| A | レコードID | `APP000001` 等、取込ごとに付与する仮ID。**人を識別する永続IDではない** |
| B | 企業ID | 文字列。先頭ゼロ保持、企業名は編集マスタで解決 |
| C | 仕事番号 | 文字列。JOINキー。先頭ゼロ・表記揺れに配慮 |
| D | 求人参照ID | `93_求人分析マスタ` への内部参照。求人情報なしは空欄 |
| E | 求人CSV突合フラグ | `1/0`。**実求人CSVとの突合のみ1**。埋込求人情報による補完では1にしない |
| F | 応募日付 | `YYYY-MM-DD`（ローカル日付）。**元の時分秒を保存しない** |
| G | 応募年月 | `YYYY-MM`、表示用・比較用。Fから再生成可能 |
| H | 月内応募日 | `1～31`、月内バケット分析用。Fから再生成可能 |
| I | 応募曜日 | 月～日、Fから再生成可能 |
| J | 応募時間 | `0～23`、1時間単位。元の分秒は保存しない |
| K | 応募数 | 原則1。応募行数で集計する場合も仕様上の検証用として保持 |
| L | 対応状況 | 正規化ラベル。原文の自由記述は持たない |
| M | 応募媒体 | 正規化ラベル |
| N | 年齢 | 数値または空欄。**年代だけにしない**（ターゲット下限・上限の変更に必要） |
| O | 性別 | 男性／女性／未回答／不明 |
| P | 氏名文字種区分 | CSV取込時に一時的に氏名から生成する分類。氏名原文は残さない |
| Q | 居住都道府県 | 都道府県または空欄。市区町村・詳細住所は残さない |
| R | 勤務地・居住都道府県一致 | 一致／不一致／不明。必要な値が欠ける場合は不明 |
| S | 職種 | 求人マスタの代表属性を転記した表示用コピー |
| T | 雇用形態 | 同上 |
| U | 勤務地都道府県 | 同上。詳細住所は持たない |
| V | 求人勤務地名称 | 同上。名称に機微情報が含まれる場合は内容を確認 |
| W | 求人分析情報ソース | `JOB_CSV`／`APPLICATION_EMBEDDED`／空欄 |

- `S:V` は **表示補助**。`93_求人分析マスタ` を分析の正本として参照し、マスタをGASが構築する時に同期出力する（ユーザーがS:Vを手修正しても正本としない）。
- `G:I` も便利用の派生列。`F` を日時解析の正本とし、タイムゾーンを `Asia/Tokyo` に固定／明示。
- `N` の年齢は個人情報リスクがあるため共有権限に注意。必要性は自由なターゲット範囲の再集計に基づく。
- `O:P` は既存Web版の性別・氏名文字種分析との互換に用いる。取込時に元氏名を使った後は原文を送信・保存しない。**現行Web版は月（YYYYMM）＋氏名で重複判定する**ため、重複排除と文字種判定をブラウザ側で終えてから氏名を破棄する。同姓同名・同月の別人を誤って重複扱いする既存制約は引継ぎ、テストする。
- `20_突合データ` に書かれたデータは「匿名データ」と呼ばない。**日時・求人キー・年齢・属性の組合せによる再識別の可能性**がある。

## 3. `93_求人分析マスタ` 保存列（20列案）

| 列 | 保存する項目 | 形式／理由 |
|---|---|---|
| A | 求人参照ID | `20_突合データ` からのJOIN先 |
| B | 求人分析情報ソース | `JOB_CSV`／`APPLICATION_EMBEDDED` |
| C | 企業ID | 文字列 |
| D | 仕事番号 | 文字列 |
| E | 求人管理番号 | 画像の公開求人照合などに必要な場合のみ。不要なら最終版で除外 |
| F | 仕事名 | 仕事名KW抽出の**元データ**として保持 |
| G | 職種 | 分析軸 |
| H | 雇用形態 | 分析軸 |
| I | 募集背景 | 分析軸 |
| J | 求人勤務地名称 | 分析軸 |
| K | 勤務地都道府県 | 分析軸。詳細住所は残さない |
| L | 求人備考1行目 | **原文全文は保存しない**。必要なら個人情報・内部メモの検査を通した1行目のみ |
| M | 給与区分コード | 文字列。給与名は共通マスタで復号可能 |
| N | 給与金額MIN | 数値／空欄。給与下限のバケット変更に必要 |
| O | メイン画像ファイル名 | TOP画像別集計用 |
| P | 求人画像枚数 | 数値 |
| Q | 求人動画あり | 1／0／空欄（埋込ソースで不明な場合は空欄） |
| R | Indeed求人タグコード | `::` 区切りの元コード。名称マスタの変更後も再集計可能 |
| S | Indeed求人タグ数 | 数値（コードから再生成可能） |
| T | 求人原稿文字数 | 数値（現行Web版の同一定義でCSVアップロード時に算出） |

- `93_求人分析マスタ` は通常は非表示とし、値はGASが全更新する。**非表示は秘匿手段ではない**ため、上記以外の原文や機密情報を入れない。
- 応募CSV内の埋込求人属性は `APPLICATION_EMBEDDED`。この行に給与、画像、動画、タグ、原稿文字数などCSV専用値を推測入力しない。
- 元求人CSVに一致する場合、`JOB_CSV` の非空属性を優先し、必要なら応募CSV由来の同義属性で欠損補完する。**求人CSV突合率は別指標で維持**。
- `給与金額MAX`、詳細勤務地住所、最寄駅、長文仕事内容、全文備考、動画タイトル、メールドメイン等は、現行30分析軸の再集計に必須ではないため初版の保存対象から除外する案。
- `求人備考1行目` は自由記述由来で内部情報・個人情報が混在する可能性がある。**初版は既定で保存・分析しない安全側の提案**。必要な場合だけ保存対象として許可する運用・検査ルールを別途確定する。その場合、「求人備考1行目」軸は初期状態では利用不可。
- ファイル名・仕事名・勤務地名・備考は文字列。**先頭`=`などを数式として実行させないサニタイズが必要**。

## 3.1 `94_画像マスタ`（新規・画像候補／取得状態）

既存Web版の画像解決処理は、**分析対象TOP画像のファイル名**だけでなく、同じ画像を使う**公開求人の管理番号**を候補としてWorkerへ渡す。現行Web版では「`公開情報区分=6` かつ数値の求人管理番号」の求人CSV全行から候補を探し、同一画像ファイル名の候補を重複排除している。求人CSVと突合した1求人1行の`93`だけでは、未突合の公開求人にある候補を再現できない。

したがって、RAW求人CSVを破棄する**前**に画像ファイル名ごとの候補を抽出し、次の最小データを保存する。

| 項目 | 内容 |
|---|---|
| 画像ファイル名 | 画像集計対象のTOPファイル名 |
| 公開求人候補ID | 同一画像を持つ公開中求人の数値管理番号を重複排除して保存。候補なしは空欄 |
| 画像URL | Workerが解決したURL（未取得なら空欄） |
| 取得状態 | 未取得／自動取得／候補なし／取得失敗 |
| 最終取得日時 | Worker確認時の日時 |

- **応募と求人CSVが実際に突合した画像ファイル名を分析対象とする**。公開中候補IDを探す元データには、JOINに使われなかった求人行も含めた求人CSV全行を利用する。
- Workerの後日再実行は、この最小候補とファイル名でできる設計にする。応募者情報や求人CSV全文は保存しない。
- CSV全件更新後も、ファイル名と候補IDが一致するなら旧URL／取得状態を適切に引き継げる設計とする（手動URL修正については別途決定）。
- Workerの取得失敗で応募・求人分析自体が止まらないよう分離する。

## 3.2 分析30軸の保存データ対応

| 区分 | 分析軸 | 再集計に必要な列 |
|---|---|---|
| A 応募由来（11） | 対応状況、応募年月、応募媒体、性別、氏名文字種区分、居住都道府県、企業ID、月内応募日、応募曜日、応募時間帯、勤務地・居住都道府県一致 | `20`のL、F/G、M、O、P、Q、B＋企業IDマスタ、F/H、F/I、J、R |
| B 求人補完可（8） | 職種、雇用形態、求人勤務地名称、勤務地都道府県、募集背景、仕事名KW、仕事名フルKW、求人備考1行目 | `93`のG、H、J、K、I、F＋KWマスタ、F＋KWマスタ、L（備考は初期OFF案） |
| C 求人CSV専用（11） | 給与区分、時給／日給／月給／年収下限、求人原稿文字数、メイン画像有無、求人画像枚数、TOP画像ファイル名、求人動画有無、Indeed求人タグ数 | `93`のM＋給与マスタ、M/N、T、O、P、O＋`94`、Q、R/S＋タグマスタ |

- **11+8+11=30軸**がデータモデル上では構成可能（ただし求人備考は安全上初期OFF案）。
- `93`の`求人分析情報ソース` と`20`の求人CSV突合フラグは分離し、求人CSVなし・応募CSVの埋込求人情報ありでもB群は有効となるようにする。
- 列番号はこの仕様を説明する便宜上の記号。実装では名称に基づく列定義とテストで管理し、インデックスをハードコードしない。

## 4. RAWから書込までの責務

1. スプレッドシート内のHTMLダイアログで応募CSV／求人CSVを読込。**CSV_A／CSV_Bをファイルごとに文字コード判定・ヘッダー正規化**。
2. ブラウザ内で既存Web版相当の重複除外・求人JOIN・埋込求人属性fallback、氏名文字種などの**元データが必要な派生属性を算出**。
3. 氏名・メール・電話・詳細住所・応募者原文・全CSV行を廃棄し、**応募・求人・画像候補の必要列ホワイトリストだけ**送信する。エラー報告・ログにも含めない。画像は第3.1節の候補表を参照。
4. コンテナバインドGASは厳格な列名・型・件数・参照整合性・数式混入・サイズの検証後、値を書き込む。送信データ自体も信頼せず検証する。
5. CSV更新は**毎回全件置換**。まず新データを検証し、旧データの復旧可能状態を確保してから入替に着手する。**Sheetsの複数タブ書込は原子的ではない**ため、途中失敗時は更新中表示・前回データの退避・復元を組み合わせる。詳細は[CSV取込・安全更新設計](CSV_IMPORT_UPDATE_SPEC_DRAFT.md)を参照。
6. 「設定を反映」では `20` と `93` の正本データから再集計し、CSVの再読込やJOINは行わない。設定による年齢区分・ターゲット・仕事名KW・タグ名称の更新が可能であることを確認する。
7. 時間情報は日付と**時間（0～23）**を保持すれば、月別・日別・曜日・時間帯分析に利用できる。分単位・秒単位の分析追加が必要になれば元CSVの再アップロードが必要。

## 5. シートならではの技術要件

- **型固定**：企業ID、仕事番号、求人管理番号、求人参照ID、タグコードは数値変換せず文字列で保存。先頭ゼロを保持。
- **数式混入防止**：Apps Script `Range.setValues()` は `=` で始まるCSV由来文字列を数式として解釈する。出力はホワイトリスト・値の型検証・文字列の数式無害化を行う。フォーマット指定だけに依存せず検証する。
- **列位置固定**：プログラムは定義されたヘッダー名で書き込む。必要に応じヘッダー一致を確認し、利用者が手動で列追加・移動した場合は勝手に上書きせずエラー／再整形を案内する。
- **行数は可変**：全件を保存し、過去の行数が多い場合は残余セルの**内容だけ**削除。初期化時に確保する列幅・条件付き書式・フィルタ等は更新で消さない。
- **編集範囲**：設定・マスタはユーザー編集。正本突合データ・求人分析マスタはGASが書き込む領域。保護は誤操作防止であり、情報秘匿を意味しない。
- **多人数利用**：利用者は空のテンプレートをコピー。コピー時に新しいスプレッドシートとバインドスクリプトができる。初回の権限承認以外に中央サーバーの登録を必要としない構成。
- **性能**：全件一括の元CSVをSheetsへ置かない。応募・求人を分離して同じ求人属性を応募数分だけ重複保存しない。実際の処理速度は件数別に測定。
