# 表示仕様・初期設計（v0.1 / 検討用）

- 作成日：2026-10-15
- 対象：`tsicb/valid-app-sheets`
- 状態：**表示仕様の提案（未承認・未実装）**。シートテンプレート／GAS／HTMLアップローダーはまだ存在しない
- 参照正本：[valid-app](https://github.com/tsicb/valid-app)、[分析軸30種の可用性仕様](https://github.com/tsicb/valid-app/blob/main/docs/ANALYSIS_AXIS_AVAILABILITY.md)
- 原則：「元データの分析定義はなるべく共通、UIはGoogle Sheets向けに再設計」「手動書式変更は日常実行で極力保持」

## 1. 画面・タブ構成（案）

| タブ | 表示 | 役割 | 日常の書込主体 |
|---|---|---|---|
| `00_ホーム` | 表示 | KPI、データ更新状況、操作案内、エラー要約 | GAS（数値・時刻・状態セルのみ） |
| `20_突合データ` | 表示 | 1応募=1行の加工後明細、フィルターで検証 | GAS（値・列構造は固定） |
| `30_分析設定` | 表示 | 期間、年齢、集計幅、表示ON/OFF、表示件数、マスタリンク | ユーザー（入力セル）／GAS（検証メッセージのみ） |
| `40_基本分析` | 表示 | 基本指標を1タブで切替。**列軸は年代に固定** | GASは集計キャッシュ、シート関数は表示 |
| `41_応募進捗` | 表示 | 応募推移、月比較、グラフ | GAS（集計値）、シート側グラフ |
| `42_カスタム分析` | 表示 | 行最大3軸＋列1軸の自由集計 | ユーザー（軸設定）／GAS（行列データ） |
| `43_TOP画像` | 表示 | TOP画像と応募傾向、ファイル名、画像付き大きな行 | GAS（集計値と画像参照） |
| `44_Indeedタグ` | 表示 | タグコード／名称・求人件数・応募傾向 | GAS（集計値） |
| `90_基本集計キャッシュ` | 非表示 | 基本分析各指標の集計済み出力 | GAS（値のみ） |
| `91_集計補助` | 非表示 | 必要な集計表・ドロップダウン候補・補助データ | GAS（値のみ） |
| `92_運用管理` | 非表示 | データ世代、処理時間、最終正常完了、内部チェック | GAS |
| マスタ類 | 基本は表示／必要なら別タブ | 仕事名KW、企業ID表示名、Indeedタグ名称など | 初期値＋ユーザー編集（実態に応じて決定） |

`10/11_応募/求人RAW` は現段階では設けない。CSV投入は後述のHTMLダイアログで行う。

## 2. 全タブ共通の画面規則

- **タブ自体を更新時に削除・再作成しない**。固定の入力範囲と表示範囲を持つ。
- 通常更新では値と必要な数式／画像参照だけ変更する。**列幅・行高・背景色・文字色・罫線・条件付き書式・フィルター・固定行列は変更しない**。
- 見出しと入力欄を分離。入力可能セルを明確化し、GASの書込先と重複させない。
- 表の件数増減・指標切替で旧値が残らないよう、前回出力範囲の**内容のみ**クリアしてから上書き。書式は原則残す。
- 全表に表示対象期間、対象年齢／ターゲット年齢、最終集計日時、データ世代（バージョン）を表示。
- データソースが無い指標は選択候補から除外する。ただし期間・年齢フィルターで一時的に0件になった場合は候補を維持し「現在の条件では集計対象データがありません」を表示。
- 欠損のラベルは原因別（不明／未設定／求人情報なし／タグなし）に区別。求人CSV突合率と応募CSV由来求人情報の補完率を混同しない。
- レイアウトの形が変わる「初期レイアウト作成／再整形」と、日常の「データ更新」は別操作。後者は利用者の書式を勝手に初期化しない。
- 切替表の表示可能行数は固定領域を先に用意する。上限超過時に無断で列幅・書式を再構成せず、通知して拡張方法を案内する（行上限値は要決定）。

## 3. `00_ホーム`（案）

上から次の順で固定カード／固定セル表示。

1. **総応募数／ターゲット応募数／ターゲット率／求人CSV突合率**。ターゲットは原則、設定された年齢範囲の応募者を指し、「採用・選考結果が良好」という意味の有効応募とは区別。
2. **対象期間・対象年齢・ターゲット年齢**の説明。ターゲット定義のラベルを常に表示。
3. **データ更新状態**：最終正常CSV取込日時／最終再集計日時／元応募件数／求人突合件数／CSV埋め込み補完件数／除外件数／エラー件数。設定変更後の「再集計未反映」も表示。
4. **使い方**：上部カスタムメニュー「CSV取込・全更新」「設定を反映」「カスタム分析再集計」の案内（操作自体はGASメニューを正とする）。

値のない状態、読込エラー、分析データなしは別のメッセージにする。

## 4. `20_突合データ`（案）

- 応募1件=1行。ヘッダー固定、フィルターを有効にする。基本的にユーザーが手で上書きする対象にはしない。
- 例示列（暫定）：行番号、応募日（分析に必要な粒度）、応募年月、応募曜日、応募時間帯、年齢（数値）、年代、ターゲット年齢フラグ、性別、氏名文字種区分、居住都道府県、応募媒体、対応状況、企業ID、仕事番号、職種、雇用形態、求人勤務地名称、勤務地都道府県、勤務地・居住都道府県一致、募集背景、仕事名KW、求人備考1行目、求人分析情報ソース、求人CSV突合フラグ、必要な給与／画像／タグ関連の派生列。
- **氏名、メールアドレス、電話、詳細住所、応募者の自由記述、RAW全文等は保存対象から除外**する。表示要件に不要な項目は最初から送らない。
- 応募者の年齢・応募日・企業・求人番号の組み合わせでも個人を推測できる可能性がある。保存列の最終決定とシート共有範囲は別途プライバシー検討が必要。
- CSVを新しく読み込んだときは原則**全件置換**。追加入力／差分更新・重複判定の永続ID設計は初版対象外。
- 項目名と出力位置は定義テーブルで固定し、シート関数の参照が崩れないようにする。

## 5. `30_分析設定`（案）

| 設定グループ | 主な項目 | 反映方法 |
|---|---|---|
| 集計範囲 | 集計開始日／終了日、分析対象年齢の下限／上限 | 「設定を反映」で再集計 |
| ターゲット | ターゲット年齢の下限／上限 | 「設定を反映」で再集計 |
| 基本分析 | 表示ON/OFF、出力件数、カテゴリ表示順（既存版のルールを基本） | 「設定を反映」でキャッシュ作成 |
| 集計バケット | 時間帯、給与幅、画像枚数、Indeedタグ数、原稿文字数等 | 「設定を反映」で再集計 |
| 応募進捗 | 日別／累積、比較対象月数、予測線表示（候補） | グラフ参照データ更新 |
| 専用タブ | TOP画像表示数、Indeedタグ表示数 | 「設定を反映」で再集計 |
| マスタ | 仕事名KW、企業ID表示名、Indeedタグ名称等 | 更新反映時に再集計 |

- 指標表示ON/OFFは既存Web版とできるだけ名称を一致させる。
- 入力値検証（開始日<=終了日、下限<=上限、数値範囲、マスタ未設定）を行う。
- **基本分析の年代列自体は固定**。基本表の列軸切替／5歳ずらしを同タブには持ち込まない。
- 一部の設定を変更しても「表示プルダウンのみ」の切替であればGASは実行しない。

## 6. `40_基本分析`（1タブ切替・固定列）

### 操作領域

- 上部：分析指標選択プルダウン、対象期間・対象年齢・ターゲット条件・基準応募集合（全応募／求人分析情報あり／求人CSV突合済み）。
- 分析指標候補は既存版の基本表を起点とし、設定ON＋データ利用可能のものだけ候補に出す。
- **応募年月は行軸として選択してよいが、列軸としては使わない**。年月クロスはカスタム分析に任せる。
- カスタム分析専用の `給与区分` は原則基本分析の対象外。
- プルダウンを変えるだけなら、`90_基本集計キャッシュ` から表示させる。原則GAS実行なし。

### 表レイアウト（提案固定列）

| 列 | 意味 |
|---|---|
| A | 選んだ指標のカテゴリ（職種／媒体／雇用形態など） |
| B | 総応募数 |
| C | ターゲット応募数 |
| D | ターゲット率 |
| E～L | 10代、20代、30代、40代、50代、60代、70代、その他 |

この8年代は現行`valid-app`の通常年代モードと整合する初期案。原則列位置を変えず、対象年齢で一部年代が対象外になっても列を削除しない。対象年齢による部分年代の混在は画面上に集計条件として明示する。

- 5歳ずらしモード／自由年齢幅は、列幅変更を避けるためカスタム分析で扱う案。
- 件数降順を基本、月・曜日・数値幅は時間／数値順、欠損は原則最後。
- 合計は対象集合に対するもの。**ターゲット率=C/B**。応募数が0の行は「-」等の非数値表示。
- 行のカテゴリ・件数が変わっても、列幅や背景色などはGASでリセットしない。ただし**行番号に固定した色は別カテゴリへ引き継がれ得る**ためカテゴリ色は条件付き書式やデータ列に基づくルールを推奨。
- 表の出力件数は基本設定で制御。表示範囲に入りきらない場合の上限値は後続設計で決める。
- 基本表に大型グラフは置かず、数値と比較の見やすさを優先。

## 7. `41_応募進捗`（グラフ専用）

- 上部：期間・集計条件、月ごとの合計、直近月の到達件数。
- グラフ本体：横軸=月内日付（1～31日）、縦軸=応募件数、最新月と比較月を表示する。日別／累積は選択切替の対象。
- シリーズ数が増え過ぎる場合の上限を決め、見やすさを優先する。設定欄は固定、チャート位置・サイズは固定。
- 月別集計表（年度月・応募数・ターゲット応募数など）はグラフの下に配置。
- 現行Web版の最新月の着地予測は**後続候補**とし、まず月別日別／累積の正確性を優先する。
- チャートを毎回削除・再作成せず、参照する集計表を更新して継続表示する。

## 8. `42_カスタム分析`（可変行列・GAS再集計）

- 上部：行軸1（必須）、行軸2／3（任意）、列軸（必須）、集計対象年齢、指標（初版は応募数を基本。ターゲット応募数／ターゲット率への切替は追加候補）。
- 行・列の重複軸禁止。指標候補は **設定ON＋保存済み元データで利用可能**。フィルターだけ0件なら候補は残す。
- 30分析軸の取得元・利用可否の定義は既存Web版の文書を基準にする。
- 応募年月は**行軸にも列軸にも選択可能**。基本分析側で削った年月クロスをここで吸収する。
- 選択された軸に応じて対象応募集合を `全応募`／`求人分析情報あり`／`求人CSV突合済` の順に必要な狭さへ切り替える。
- 組合せ数が多いため **カスタム分析は「集計実行」メニュー／ボタン** を使う。軸セル編集だけでは本体集計を走らせず「変更未反映」を表示する。
- 可変列数の表を固定出力開始セルから展開。セル色の意味が列ラベル変動によりずれるため、カテゴリ固定色より数値別の条件付き書式を優先。ユーザーが調整した列幅は変更しない。
- 行・列数に安全な上限を設け、超過時は切り捨てなのか実行拒否なのかを明示（閾値未確定）。大量の全組合せ事前キャッシュは行わない。
- データがない場合は「現在の条件では集計対象データがありません」。元データ欠損や設定不正は別メッセージ。

## 9. `43_TOP画像`（画像付き表）

- 一般の基本表よりも**行高を大きく固定**した専用表を持つ。
- 基本列案：画像サムネイル／画像ファイル名／該当求人数／総応募数／ターゲット応募数／ターゲット率／年代別内訳（必要なら後ろに固定追加）。
- 画像ファイル名単位で集計し、同じ画像を複数求人で使用する場合は1行にまとめる。画像がない求人は「（TOP画像なし）」で区別。
- TOP画像と応募・求人の対応データは**求人CSV突合済み**を基準にする（応募CSVの埋め込み求人情報だけでは画像を成立させない）。
- 画像URLがない場合はファイル名のみ表示、外部画像URLが利用できない場合は代替表示。既存Web版の画像解決Workerは将来の再利用候補。
- 一定の表示件数で制限、超過件数を注記。画像の取得・描画失敗で集計全体が止まらないようにする。
- GAS更新で画像行の高さ・幅・書式を勝手に再設定しない。

## 10. `44_Indeedタグ`（タグ専用表）

- 基本列案：タグコード／タグ名／使用求人数／総応募数／ターゲット応募数／ターゲット率／年代別応募数（必要であれば固定列）。
- **1求人に複数タグ**がある場合は各タグへ応募が計上される。したがって**タグ別の応募数を合算しても、全応募数と一致しない**。注記を必ず表示。
- 同一求人に同じタグが重複していても1回として扱う。タグ名未登録のコードはコード付きラベルを表示。
- タグなしは独立カテゴリ。全件タグなしなら「分析できるタグがありません」を表示。
- 件数制限・並び替え（原則ターゲット応募数、次に総応募数）を設定で制御。
- 求人CSV突合済みの応募を基準にする。応募CSV内の求人情報だけでIndeedタグを捏造しない。
- シートの特徴を活かし、タグコード・名称をコピー／フィルターできるようにする。

## 11. 内部キャッシュと更新操作

### 2種類の集計と表示切替

| 操作 | 入力 | 主な処理 | 出力 |
|---|---|---|---|
| CSV取込・全データ更新 | ブラウザ上の応募CSV・求人CSV | 形式判定→正規化→突合→必要列への削減→明細保存→基本／進捗／画像／タグ再集計 | 全データ・基本キャッシュ・専用タブ |
| 分析設定を反映 | 保存済み突合後明細＋設定 | 再突合せず再集計 | 基本キャッシュ・進捗・画像・タグ |
| 基本分析の指標プルダウン | 集計キャッシュ | シート関数による選択・転記 | 基本分析タブのみ（GAS実行なし） |
| カスタム分析を集計 | 保存済み突合後明細＋軸指定＋設定 | 選択組合せだけをGAS集計 | カスタム分析表 |

- 設定変更後・CSV更新後に古い表を新しい結果と誤認しないため、`最終更新日時` と `設定変更未反映` の表示を分ける。
- 実行時は開始・終了・処理件数・処理時間・失敗段階を内部管理に残す。**個人情報／CSV全文はログに残さない**。
- CSV取込が失敗した場合は、前回の正常なデータ／表示を不用意に消さない方針とする（後続で具体的な書込単位・復旧方法を設計）。
- 基本分析キャッシュは **指標別の集計済み表** を保持し、軸変更時に元明細を全件再計算しない。
- `20_突合データ` にRAW由来の全ての列を保持する必要はないが、**設定変更で再計算できる列**は残す。年齢は年代ラベルだけでなく数値年齢を保持する必要がある。

## 12. プライバシー・データ管理（初版の必須要件）

- CSV取込HTMLで可能な範囲をブラウザ側で正規化・突合し、**保存許可列のみGASに送る**。RAW氏名・メール・住所・電話等をSheetsへインポートしない。
- `google.script.run`等でRAW全体をGASへ渡せば「シートには保存していない」が「サーバーには渡っている」状態になるので、両者を区別する。
- 保存された突合明細は匿名化済みと断定しない。年齢、日時、企業、仕事番号などは組み合わせにより再識別リスクがあるため、共有範囲・必要列・保持期間を別途評価する。
- 本リポジトリは**公開**。実応募データ／認証情報／機密CSVをコミットしない。設計・テストは架空データで行う。
- RAWを保存しない構成では、後から新しい列やマスタに基づく正規化をやり直す際、再アップロードが必要になる場合がある。

## 13. 設計上の確認・保留事項

1. **基本分析の年代8列**（10～70代＋その他）を固定するか。「その他」を「80歳以上」「不明」に分割するかは既存版との互換性との比較が必要。
2. 基本分析は当面 **総応募数・ターゲット応募数・ターゲット率・年代別応募数** の固定12列とする案。年代別ターゲット数まで横に持つかは確認。
3. 表示件数・可変出力領域の上限（例：50行／200行、カスタムの列数上限）は実データ規模を見て確定する。
4. カスタム分析の指標を「応募数」のみから始めるか、最初から「ターゲット応募数」「ターゲット率」を追加するか。
5. 応募進捗の比較月数・着地予測・グラフ系列数、シートでの描画仕様。
6. TOP画像の外部URL取得を初版に入れるか、まずファイル名・件数の表示で始めるか。
7. 仕事名KW・企業名・Indeedタグ名称等のマスタ編集画面と権限。
8. 個社テンプレートを複製運用する際のGAS配置（バインド型／独立GAS）とバージョン配布。
9. 初版の全データ置換前提を維持するか、増分追加・履歴データ統合を必要とするか。
10. 読み書き件数に応じた処理速度測定、途中失敗時の復旧、書式維持の自動テスト。

**次工程**：本資料をレビューし、特に `40_基本分析` と `42_カスタム分析` の列・行・指標・実行ボタンの仕様を確定。その後、`20_突合データ` に保持するcanonical列とテンプレートのセル位置を固定する。コード実装はその後。
