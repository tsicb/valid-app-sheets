# カスタム分析 v0.1：30軸 × 行最大3・列1 × 3指標

- 対象：`tsicb/valid-app-sheets` の既存Google Sheetsテンプレート
- 状態：**GitHubのGAS初版実装・自動テスト完了。Google Sheets実環境での表示／性能／容量は未検証。**
- 既存Web版参照：`tsicb/valid-app/analysis-core.js` の `customAxisOptions()`、`customAxisDataScope()`、`customAxisValue()`、`aggregateCustom()`
- 取得可否の正本：`tsicb/valid-app/docs/ANALYSIS_AXIS_AVAILABILITY.md`（30軸）
- **CSV再取込、テンプレート再生成、既存の基本分析・応募進捗の再実行は不要。**

## 1. 操作

1. Google Sheets →「拡張機能」→「Apps Script」で **`gas/11_CustomCore.gs`・`gas/12_CustomSheet.gs` を新規作成**し、GitHubのコードを貼る。
2. **`gas/01_EntryPoint.gs` を最新版へ全文差し替え**、保存後にスプレッドシートを再読込。
3. `有効応募分析 → カスタム分析候補を更新` を一度実行。現在保存されている応募・求人の取得状況と `30_分析設定` の表示ON/OFFに基づいて、候補を `92_運用管理!J:K` へ記録し、`42_カスタム分析!B3:B5/E3` のプルダウンを更新する。**現在の期間／対象年齢によって0件になっても候補自体は消えない**。
4. `42_カスタム分析` で軸と指標を選択（B3=行軸1必須、B4/B5=行軸2/3任意、E3=列軸必須、E4=表示指標）。
5. メニュー `有効応募分析 → カスタム分析を実行` を押す。選択した軸と指標によるクロス表を **A12以降へ書込**。行・列カテゴリは全件出力し、上位件数による省略はしない。
6. 軸、設定、マスタを編集しても**重い集計は自動実行しない**。A8に「設定変更あり・カスタム分析未反映」が表示されるため、必要なときに再実行する。

## 2. 30分析軸の取得範囲（Web版に合わせる）

- **A. 応募側11軸**：対応状況／応募年月／応募媒体／性別／氏名文字種区分／居住都道府県／企業ID／勤務地・居住都道府県一致／月内応募日／応募曜日／応募時間帯。
- **B. 求人分析情報側8軸**：職種／雇用形態／求人勤務地名称／勤務地都道府県／仕事名KW／仕事名フルKW／募集背景／求人備考1行目。求人CSV未突合でも応募CSV埋込の求人属性で分析できる場合は候補。
- **C. 求人CSV側11軸**：給与区分／時給下限／日給下限／月給下限／年収下限／求人原稿文字数／メイン画像有無／求人画像枚数／TOP画像ファイル名／求人動画有無／Indeed求人タグ数。

**候補判定は未フィルターの保存済みデータと「表示項目」のON/OFFを参照**。性別は固定23列の応募明細に存在。企業IDは `31_マスタ編集` の有効な企業ID表示名がある場合に候補化。都道府県一致は判定結果を持つ応募がある場合に候補化。求人情報系は元値に有効な内容がある場合だけ選択可能。メイン画像有無・画像枚数・動画有無・タグ数はJOB_CSV行がある場合に「なし／0」の集計も可能。

給与区分はWeb版の例外処理と同様、給与下限4軸のうち**取得可能かつ表示ONの軸が1件以上**ある場合にのみ候補へ表示。TOP画像ファイル名のON/OFFは基本分析の29軸とは独立した「TOP画像別応募傾向」のI列チェックに連動。

## 3. 対象応募を選ぶルール

軸の選択セットによって、次のうち**最も限定的な集計対象**にそろえる。

| 使われる軸 | 集計対象 |
|---|---|
| 応募側のみ | 応募データ全件（期間・対象年齢フィルター後） |
| 求人分析情報側が含まれる | 求人分析情報のある応募（JOB_CSV／APPLICATION_EMBEDDED） |
| 求人CSV側が含まれる | 求人CSVと突合済みの応募のみ（フラグとJOB_CSVソースを併用判定） |

給与区分が不一致（「時給下限」を選んでいるが対象求人が月給など）のレコードは、Web版同様、その軸でカテゴリ化できないため集計から除外する。

## 4. 集計と出力

- 行軸1～3を **A:C列**、行合計を **D列**、列軸のカテゴリを **E列以降** に出力。末尾には「列合計」行を置き、**D列に総合計**を表示。
- E4の指標は **応募数／ターゲット応募数／ターゲット率** の3択。今回は表示指標を1つずつ切り替えるUIであり、同時3段表示ではない。切替後は再実行が必要。
- ターゲット率は同じ交点の `ターゲット応募数 ÷ 応募数`。行合計・列合計・総合計は**分子・分母を合計してから再計算**し、率を単純平均しない。
- 仕事名KWは `31_マスタ編集` の有効KWを登録順で照合。求人備考はマスタに保管した全文から1行目だけを集計時に抽出。
- 日付・年齢フィルターとバケット幅は `30_分析設定` を共有。月内応募日、時間帯、給与下限帯、原稿文字数、画像枚数、Indeedタグ数に対応。
- 書込時は **A12からの矩形**のみを更新。前回より列・行が減ったときの残余セルは`clearContent()`で内容だけ除去し、列幅や背景色などを残す。
- **100列での一律打切りをしない**。必要なセル数を事前に計算し、Google Sheetsの列上限（18,278列）・スプレッドシートの10,000,000セル上限を超える見込みなら**省略せずエラーで中止**。極端に大きなデータではApps Script実行時間制限の影響を受ける可能性がある。
- **出力途中にエラーが発生した場合**は、適用済み状態をあらかじめ無効化する。途中の表を「反映済み」と誤認させず、A8に再実行が必要と表示する。応募・求人の元データは変更しない（大規模な中間結果の完全ロールバックは初版の対象外）。
- 文字列をセルへ書くときは `vasSafeCell_()` で数式扱いを防ぐ。RAWの応募者氏名・連絡先は集計対象の保存列に存在しない。
- 候補、集計結果、適用済み設定の記録はそれぞれ `92_運用管理!J:K`、`42_カスタム分析!A12:`、`92_運用管理!A:B` のキーで管理。

## 5. 初回動作確認

最初は `42_カスタム分析` で**B3=応募媒体、E3=応募年月、E4=応募数**を選び、次を確認する。

1. クロス集計表の行・列が生成され、合計が基本分析の対象応募数と一致するか（応募側2軸なら対象期間・年齢条件は同じ）。
2. E4をターゲット率へ変更して再実行すると割合表示に変わるか。総合計は基本分析のターゲット率と一致するか。
3. B4に「職種」を追加するとJOB_CSVまたはAPPLICATION_EMBEDDEDの求人情報がある応募だけに変わるか。
4. 給与軸を使うと求人CSV突合済みに狭まるか。
5. 30設定や31マスタの編集後、A8が「設定変更あり・カスタム分析未反映」になり、実行後に「反映済み」に戻るか。
6. 列軸を少数カテゴリへ切り替え、以前の余分な列の**値**が残っていないか。
