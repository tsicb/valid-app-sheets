## 今回の使い方

1. `30_分析設定`の期間・年齢・バケット幅を設定する。
2. シートの`有効応募分析 → 基本分析を再集計`を実行する。
3. `00_ホーム!B8`に**最後に集計を実行したときの対象期間**、`00_ホーム!B9`に**最後に集計した対象年齢・ターゲット年齢**が表示される。これは現在編集中の設定ではなく、**実際に適用した条件の記録**。
4. 設定変更後は`00_ホーム!B15`と`30_分析設定!B38`に**「設定変更あり・再集計未反映」**と表示。以前の集計値とホームの適用済み条件はそのまま保持し、利用者が明示的に再集計するまで変わらない。
5. 設定値を元の状態に戻すと「基本分析反映済み」に戻る。別のCSVを全件取込した場合は世代ID差異により「CSV更新後・基本分析未反映」となる。
6. 初めてこの改修を導入したシートでは、以前の基本分析には適用条件スナップショットがないので「基本分析の再集計が必要」と表示。**CSVの再取込は不要**。

### 対象の設定項目

- 日付：`30!B5:B6`（開始／終了）
- 集計対象年齢：`30!B9:B10`
- ターゲット年齢：`30!B13:B14`
- 月内応募日幅：`30!B17`（例：7日幅 → 1-7日、8-14日）
- 応募時間帯幅：`30!B18`（例：6時間幅 → 0～5時台、6～11時台）
- `30!I5:I37`のうち、現段階の**基本分析20項目**の表示ON/OFF

対象年齢を指定しなければ年齢不明を含めるが、Web版のターゲット判定に合わせ、**年齢不明は両端未指定でもターゲット数には計上しない**。ホームで全年齢のターゲットを表示するときには「年齢不明を除く」を明示。

`31_マスタ編集`は将来のKW・名称表示機能で利用するため、現段階の基本分析20軸の未反映検知対象に含めない。

## 実環境の確認手順

1. 上記4ファイルをApps Scriptへ配置し、保存・シート再読込。
2. `有効応募分析 → 基本分析を再集計`で再集計する。ホームB8/B9とB15、設定B38を確認。
3. `30_分析設定!B13`等のターゲット年齢条件を1つ変え、B15/B38が「設定変更あり・再集計未反映」になること、ホームB8/B9には**前回適用した条件のまま**残ることを確認。
4. 条件を元の値に戻して「基本分析反映済み」に戻ることを確認。
5. `30!B17`を7、`B18`を6にして再集計し、`40_基本分析!B3`で「月内応募日別」「応募時間帯別」を選び、範囲ラベルになることを確認。B3の選択だけでは再集計は走らない。
6. 取込データを上書きする必要はない。確認用CSVの全件取込を行う場合はテスト用コピーを利用。
