# CSVアップローダー・全件更新・障害復旧の設計（v0.3 / 初版コード実装）

- 作成日：2026-10-16
- 対象：`valid-app-sheets`（コンテナバインドGAS＋HTMLダイアログ）
- 状態：**HTML CSVアップロード、ブラウザ内正規化／JOIN、GAS分割受信・段階保存・全件置換・復旧の初版コードをGitHubへ実装済み**。Google Sheets実環境での統合テストは未実施。各分析の集計・画像Worker接続は今後実装
- 関連：[表示仕様](DISPLAY_SPEC_DRAFT.md)／[保存列の候補](JOINED_DATA_MODEL_DRAFT.md)／[Web版](https://github.com/tsicb/valid-app)
- 目的：CSV取込時にRAW個人情報をシート／GASへ渡さない。全件置換を簡単にし、再集計・書式保持・失敗時の復旧を可能にする。

## 1. ユーザーが使う3つの操作

| シートの「有効応募分析」メニュー | 実行内容 | CSVファイル選択 | 集計結果 |
|---|---|---|---|
| **CSV取込・全件更新** | CSV正規化→重複除外→求人突合→個人情報除外→データ入替（実装済み）、分析再集計（未実装） | 必要（応募は必須、求人は任意） | 取込明細とホームの一部KPI更新まで |
| **分析設定を反映** | 保存済み応募明細と求人マスタから再集計 | 不要 | 基本集計・進捗・画像／タグ集計を更新 |
| **カスタム分析を実行** | 指定の行軸最大3・列軸1・指標（応募数／ターゲット応募数／ターゲット率）を集計 | 不要 | カスタム表だけ更新 |

- 基本分析の「どの指標を見るか」プルダウンは、集計済みキャッシュを切り替えるため**GAS実行なし**。
- TOP画像のURL解決は既存Workerを利用。ただし取得失敗や待ち時間で応募分析の全件更新を失敗扱いしない。画像の再取得は別メニューにできる。
- シート上の設定、マスタ、条件付き書式、手動列幅・行高はCSV全件更新で初期化しない。
- 初回シートコピー利用時はGASの承認が必要。Spreadsheet IDの中央登録はしない。

## 2. CSV取込ダイアログ（ユーザー操作）

1. 応募CSVを1ファイル以上選択。CSV_A（UTF-8 BOM等）とCSV_B（Shift_JIS/CP932等）は複数ファイルでも**ファイルごとに形式判定**。
2. 求人CSVは任意。アップロードしなければ既存の求人マスタを引き継がず、今回の応募CSVに埋め込まれている求人属性のみを使う。
3. 確認画面に「応募取込行数／重複除外数／分析対象数／求人CSV突合数／応募CSV埋込求人情報数／保存対象外の個人情報列」を表示。
4. 実行後に「正常完了」「更新失敗、前回の分析を保持」「復旧対応が必要」を区別して表示。**GASから正常完了の確定応答を受ける前に完了表示しない**。

初版のCSV更新は**追記ではなく全件置換**。応募CSV_A/Bの複数ファイルをまとめて取り込む場合も、CSV同士を正規化後に結合して1つの新世代にする。

## 3. ブラウザ側の処理順（重要）

```text
CSV選択（応募 1～n、求人 0～n）
    ↓ ファイル単位の文字コード判定・CSVパース・ヘッダー検証
    ↓ CSV_A／CSV_B正規化、企業ID・仕事番号の文字列正規化
    ↓ 応募の重複除外  ※ここでは氏名が必要
    ↓ 氏名文字種区分、居住都道府県、応募日・時・性別を導出
    ↓ 求人CSV JOIN（企業ID＋正規化仕事番号）
    ↓ 未突合応募の求人埋込情報fallback
    ↓ 画像ファイル名＋公開求人候補IDを全求人CSVから抽出
    ↓ ホワイトリスト列だけ残す
    ↓ RAW氏名・メール・電話・詳細住所・応募者自由記述を破棄
    ↓ 求人備考は例外として求人分析マスタに全文保存する
    ↓ GASへ受け渡す直前に個人情報非混入・件数・型検証
    ↓ google.script.run 経由でデータを分割送信（必要に応じて）
```

- 既存Web版の重複キーは**応募年月（YYYYMM）＋氏名**である。CSV形式差によらず同様に判定する（初版は互換維持）。**同月同姓同名の別人を重複扱いする可能性**は既存制約として認識し、実データテストで件数を確認する。
- JOINは企業IDと仕事番号の**複合キー**。仕事番号には既存の正規化（空白・大文字化、末尾サフィックス等）の仕様を参照する。キーが欠損する行は無理にJOINしない。
- 求人CSV側の同一キー複数行では、既存Web版のJOINが**先頭行を採用**する。これを変更する場合は別途仕様変更とする。
- `JOB_CSV`／`APPLICATION_EMBEDDED` の優先順位を維持し、`求人データ突合フラグ` は実際の求人CSVとのJOINだけを表す。
- 氏名から導出する `氏名文字種区分` はWeb版のルールに合わせる。「国籍」を推定／判定する機能ではない。
- 取込時に長文から `求人原稿文字数` 等を計算し、全文は保存しない。将来、カウント対象の定義が変われば元CSVの再アップロードが必要となる。
- **求人備考はユーザー確認済みの保存対象**。求人CSV（優先）または応募CSVに埋め込まれた求人備考を、93_求人分析マスタへ**全文のまま**送る。分析の「求人備考1行目」は保存した全文から先頭行を抽出する。氏名・メール・電話などの**応募者個人情報を保存しない原則は維持**するが、求人備考という自由記述列の内容に機微情報が含まれる可能性はあり、匿名性を保証しない。
- CSVファイル名やエラーには個人情報が含まれる可能性がある。ログにファイル名の原文や行の全文を保存しない。

## 4. GAS側の受付契約（たたき台）

`saveUploadChunk(requestId, datasetId, index, rows)` のようなAPIを想定し、名前は実装で確定。

| 保存データ | 内容 | RAWなし |
|---|---|---|
| `applicationData` | 1応募1行・23列案（`20_突合データ`） | はい |
| `jobAnalysisMaster` | 1求人1行・20列案（`93_求人分析マスタ`） | はい |
| `imageCandidates` | 画像ファイル名・公開求人候補ID・URL・取得状態（`94_画像マスタ`） | はい |
| `importSummary` | 取込件数、重複件数、突合件数、発見したCSV形式、警告件数 | はい |

GAS側で検査する条件：

- 受付可能なデータセット名・ヘッダー・列順・型・文字数・1回の分割サイズ。
- 応募・求人の参照ID整合性。`求人データ突合フラグ=1` の応募は、`JOB_CSV`由来求人マスタに結びつくこと。
- `JOB_CSV`以外の行に給与／画像／タグ／原稿文字数のCSV限定値を勝手に設定しない。
- 新しい応募行数・求人行数・画像候補数・重複除外件数などの取込サマリ整合性。
- 文字列の数式解釈防止。Google Sheets の`Range.setValues()`では先頭`=`の値が数式として解釈され得るため、テキスト専用列を明示し**数式として実行されないことをテストで確認**する。
- **応募者の氏名・メール・電話・詳細住所などを送信ペイロードに含めないこと**。列ホワイトリストを検査する。ただし**求人備考全文は許可した自由記述列として送信・保存する**ため、その内容の機密性はシートの共有設定・運用上の注意事項で管理する。サーバー側で元CSV全文を受け取るAPIを設けない。
- スプレッドシートがコピー済みか／初期テンプレートが正常かを確認。列ヘッダーが勝手に変更されていたら無理に書き換えず、原因と復旧方法を提示。

`google.script.run`は非同期。巨大な一括引数による失敗を避け、分割サイズは**実測で決定**する。分割書込の順序とリトライ時の二重反映に対して、`requestId`＋`datasetId`＋`index`で冪等性を管理する。

## 5. 全件置換で前回データを守る

**Sheetsに複数タブをまたぐ原子的なトランザクションはない。** `clearContent()`直後にタイムアウトすれば、前回の表が消えたままになる危険がある。したがって**先に旧データをクリアする方式は禁止**。

### 推奨する状態と処理

| 状態 | すること | 旧データ |
|---|---|---|
| `READY` | 正常な分析が利用可能 | 現行データを表示 |
| `STAGING` | 新世代のデータを非表示の作業領域へ分割書込、全件検証 | 旧データ保持 |
| `PREPARED` | 行数・参照関係・容量を検証し、復旧用の旧データ退避を準備 | 旧データ保持 |
| `PUBLISHING` | 書込衝突を防ぎ、応募明細・求人マスタ・画像候補・集計キャッシュを書き換える | 途中で見える可能性あり、更新中表示 |
| `READY`（新世代） | 全タブと集計の検証完了後、現行世代IDを確定 | 新データに切替 |
| `RECOVERY_REQUIRED` | 途中失敗。退避済みの旧世代から復旧。復旧完了まで分析実行不可 | 復旧状態を明示 |

- 更新前に**復旧可能な旧世代の保存値**を確保する。初版は同じブック内の非表示退避タブでよいが、セル使用量増大に注意。容量不足なら**アクティブデータを変更する前に処理中止**。
- 更新時は`LockService.getDocumentLock()`などで**同時更新の競合を防ぐ**。複数の`google.script.run`をまたいでLockを保持できる前提にはせず、持続する`requestId`・世代状態も利用する。
- **退避後もユーザー操作で見える表の値が一時的に書き換わる可能性は残る**。更新表示・分析メニューの実行抑止・前回データへの復旧処理で対処する。完全な原子切替は保証しない。
- GASが途中停止したとき、次の起動で状態を確認し、作業途中の入替は再開／ロールバックする。旧データへ復旧できなければ復旧手順と警告を提示し、完了扱いにしない。
- 新データの一部だけが反映された場合は、**集計完了フラグを立てない**。複数世代のデータを混在した「正常」表示にしない。
- シートを丸ごと削除・再作成しない。列幅・色・罫線・固定行列などを保存するため、日常の更新はデータ範囲の内容だけ変更する。
- 書式だけを残して古い結果が残らないよう、旧出力範囲と新出力範囲の和集合を把握して、必要な**値セルだけ**置換・クリアする。
- 正常完了後、不要な作業世代・旧退避の掃除は**復旧可否を確認してから**実行する。

この方式は最初から実装を複雑にし過ぎないための**安全な設計方針**であり、容量の大きな案件では非表示退避タブが負担になる。性能検証の結果により具体的な世代管理方式を見直してよい。

## 6. 分析設定の再適用

- **CSVファイル選択も求人JOINも不要**。保存済み`20`／`93`／`94`と編集可能マスタを使って再集計する。
- 対象期間・年齢範囲・ターゲット年齢・集計バケット・表示ON/OFFなどを再反映する。
- 基本分析は30指標のうち**基本分析対象の指標**を全部計算してキャッシュへ書き込む。画面側のプルダウンで閲覧を切り替える。
- カスタム分析は選んだ軸組合せだけ再集計し、`応募数`／`ターゲット応募数`／`ターゲット率`の各値を正しく算出。ターゲット率は同セルの分子／分母から計算し、割合の平均を取らない。
- `00_ホーム`と`92_運用管理`の最終正常データ世代・最終集計日時を正しく更新する。
- 設定値が変わって再計算未実施の場合、旧結果を最新扱いしない（`変更未反映`を表示）。

## 7. 失敗・競合・データ不整合の試験観点

| 代表ケース | 期待動作 |
|---|---|
| CSV_A+B複数ファイル取込 | ファイル単位で正規化してから結合。住所列衝突／性別カテゴリ分裂なし |
| 旧求人CSVあり、今回求人CSVなし | 旧求人マスタは持ち越さず、今回応募CSVの埋込属性だけ反映 |
| 月＋氏名が一致する2件 | 既存ルールどおり重複候補として件数報告（過剰重複に注意） |
| 同一仕事番号が異なる企業ID | 複合キーにより別求人 |
| CSV_B埋込求人あり、求人CSV突合なし | 職種等を利用、求人CSV突合フラグ0 |
| CSVなしで設定変更 | 再突合せず新年齢・マスタで基本分析を再集計 |
| ブラウザの通信断／ダイアログ閉鎖 | STAGINGが途中なら旧データを保持、次回起動で掃除可能 |
| 途中のGASタイムアウト | 完了にせずRECOVERY_REQUIREDまたは安全な中断、旧世代を復旧 |
| 別ユーザーによる同時取込 | ロック＋世代状態で競合を拒否 |
| GASが書くセルの式らしい文字列 | 数式として実行されず、文字列として保管 |
| 全件が求人CSVと突合できない | 総応募数と求人CSV突合率の意味を保持 |
| シートに列増減／ヘッダー変更 | 不正と判定し、勝手な破壊的修復をしない |
| 新データ量でSheet容量不足 | 本番公開前に処理中止、旧データ維持 |
| 前回より行数が少ない | 旧余剰行の値だけクリアし、書式は維持 |
| 画像Workerが失敗 | 他の集計は正常完了、画像URL失敗は独立した状態 |
| 更新後の設定未反映 | ホームと該当タブに「未反映」を表示 |

## 8. 開発に進む前に残る事項

- 保持列23＋20＋画像候補列の正式ヘッダー・型・空欄の扱いの最終調整。求人備考全文の保存は確定済みで、分析時に1行目を抽出する。
- URL／画像マスタの編集可能範囲と、CSV更新時に手動修正を保持するか。
- 作業／退避用内部シートをどこまで分けるか。最大行数の実測と、バックアップで増加するセル数を確認。
- 利用者がコピーしたときの許可画面、承認がなくてもホームを表示できるか、再実行時のメッセージ。
- シート関数で基本分析表を全件表示する際の描画性能（常に特定行数を固定しない）。
- 変更対象はあくまで`valid-app-sheets`。既存Web版の`valid-app`は変更しない。

公式API仕様： [Apps Script `Range.clearContent()/setValues()`](https://developers.google.com/apps-script/reference/spreadsheet/range)、[LockService](https://developers.google.com/apps-script/reference/lock/lock-service)、[HTML `google.script.run`](https://developers.google.com/apps-script/guides/html/reference/run)、[読み書きのバッチ化](https://developers.google.com/apps-script/guides/support/best-practices)。
