- 実装日：2026-10-22
- GitHubへのコード反映：完了。**実際のGoogle Sheetsでの動作・処理時間は未検証**。
- 初期テンプレート・応募正本・求人正本・CSV取込／復旧ロジックは変更しない。
- 以前の「8-14日」「1-7日」などの `month-day` 日付誤変換対策は `07_BasicSheet.gs` に含まれ、基本分析の再集計時に適用される。

## 1. 新メニュー（ルートは4項目）

```text
有効応募分析
├─ CSVを取り込む・更新
├─ 分析結果を更新
├─ カスタム分析を実行
└─ その他・管理 ▶
   ├─ 画像関連 ▶
   │  ├─ TOP画像URLを取得
   │  └─ 取得失敗した画像URLを再試行
   ├─ 個別に再集計 ▶
   │  ├─ 基本分析を再集計
   │  ├─ 応募進捗を再集計
   │  ├─ TOP画像・Indeedタグを再集計
   │  └─ カスタム分析の候補を更新
   ├─ CSV取込の管理 ▶
   │  ├─ 取込状態を確認
   │  └─ 中断したCSV取込を破棄
   ├─ 保守・復旧 ▶
   │  ├─ テンプレート状態を点検
   │  ├─ 初期テンプレートを作成・確認
   │  └─ 旧データを復旧
   └─ 使い方・現在の実装範囲
```

危険操作の「中断したCSV取込を破棄」「旧データを復旧」には、元から実装されている **YES/NO確認**を残す。単なるメニュー変更で保護を外さない。

## 2. 「分析結果を更新」の実行内容

`updateAllAnalysis()` は **1回のロック・1回の読込**で、以下の4工程を順に処理する。

1. **基本分析**：29軸の集計キャッシュ、40タブの切替表、ホーム指標・適用条件を更新。
2. **応募進捗**：41タブの月別推移・予測キャッシュ・グラフ・月別集計を更新。
3. **TOP画像・Indeedタグ**：43・44タブの全件分類、画像表示式、応募数・ターゲット数等を更新（**外部HTTP画像取得は実施しない**）。
4. **カスタム分析の候補**：現在の保存データ・表示ON/OFFに基づく30軸の選択候補を更新。ユーザーが選択した `42_カスタム分析` の行軸・列軸・表示指標・結果表は**変更しない**。軸選択後は別メニュー「カスタム分析を実行」を押す。

共有データは `20_突合データ`（応募）、`93_求人分析マスタ`（求人）、`94_画像マスタ`（画像候補）の各1回読取。表示設定とマスタは初回読取を基準にする。段階ごとにGoogle Sheetsへの書込と `SpreadsheetApp.flush()` を伴うため、**所要時間が4分の1になる等の速度保証はない**。

処理の最後には**ダイアログ1回だけ**で、4工程の成功／失敗、基本分析の応募数・軸数、月数、画像・タグ分類数、カスタム候補数、処理秒数を要約する。

### 一部失敗した場合

- 例えばタグ名称マスタに同一コードの重複があると、TOP画像・Indeedタグ集計だけが失敗する。基本分析・応募進捗・カスタム候補更新は可能な限り継続する。
- 失敗した分析の「反映済み」記録を無効化し、各タブに再集計が必要と表示する。途中まで書かれたセルがあっても成功扱いにしない。
- **既に成功した工程の結果は巻き戻さない**。元の応募・求人データは変更しない。個別の再実行は「その他・管理 → 個別に再集計」で可能。
- 応募CSVそのものの取込に失敗した場合、分析データの一括更新は開始しない。

## 4. 反映後の動作確認

1. Apps Scriptを保存、スプレッドシートを再読込してルートが4項目になったことを確認。
2. 「分析結果を更新」を1回押す。結果をまとめた**ダイアログは1回**だけ表示されることを確認。
3. `90_基本集計キャッシュ`で`month-day`の `8-14日`／`1-7日` が日付でなく文字列になっているかを確認。 `40_基本分析`の対応ラベルも同様。
4. `40_基本分析`、`41_応募進捗`、`43_TOP画像`、`44_Indeedタグ`の件数を確認。
5. `42_カスタム分析`で設定済みの行軸・列軸・分析結果が**一括更新で変わらない**ことを確認。候補プルダウンだけは更新される。
6. 設定変更後は、必要に応じて一括更新か個別再集計。画像URLは「その他・管理 → 画像関連」から任意取得。画像URL未取得でも集計数値は使える。
7. もし特定工程が失敗した場合、まとめダイアログの要確認欄を記録し、個別に修正・再実行。**CSV原稿中の氏名等の個人情報はエラー報告へ貼らない**。
